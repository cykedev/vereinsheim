# Abhängigkeiten und Node 26 (Oktober 2026)

## Context

Der User will alle sinnvoll möglichen Updates aller Pakete in allen Apps und neuere Node-Versionen, um bekannten
Schwachstellen zuvorzukommen. Stand am 24. Oktober 2026:

- **Next 16.3.2 ist kritisch verwundbar.** Das Out-of-Band-Update vom 14. Oktober 2026 behebt zwei RCEs (Image
  Optimization mit SVG über `sharp`, `use cache` mit Typed Arrays) und einen DoS in App-Router-Apps mit Server
  Actions (GHSA-2464-fhr4-w9xw / CVE-2026-96889, GHSA-673q-mjm6-r5xr, GHSA-p3m5-59mp-jv5r). Alle drei Apps nutzen
  Server Actions. Behoben ab 16.4.1, aktuell 16.4.3.
- `pnpm audit` meldet 6 kritische, 41 hohe, 51 mittlere Funde, die meisten transitiv (undici, brace-expansion,
  fast-uri, js-yaml, sharp, zod < 4.6.6, proxy-addr, Werkzeuge der Entwicklung wie vite, hono, MCP-SDK über `shadcn`).
- **Node:** 24 „Krypton“ ist seit dem 20. Oktober 2026 in der Wartung (Sicherheitsfixes bis April 2028). Node 26
  wird am 28. Oktober 2026 Active LTS (bis April 2029). Aktuell: 24.22.1 und 26.12.1, beide mit dem
  Sicherheitsrelease vom 21. Oktober (u. a. Brotli-Decoder Out-of-Bounds-Write, TLS-Prüfung von IP-Adressen).
- `node:26-alpine` bringt **kein corepack** mehr mit (seit Node 25 nicht mehr im Lieferumfang). Das Dockerfile ruft
  heute `corepack enable` und würde mit Node 26 scheitern.

## Approach

Ein Branch `feat/deps-node26`, ein Commit je Schritt, nach jedem Schritt `pnpm check`. Reihenfolge so, dass sich jeder
Schritt einzeln zurücknehmen lässt.

1. **Node 26** als Laufzeit überall: Dockerfile (alle drei Stufen), `.nvmrc`, `engines`, `@types/node` 26 (die Typen
   folgen der Laufzeit, [[dependency-pin-alignment]]), Texte in README, `bootstrap-dev.sh`, Kommentare. corepack
   kommt im Image über npm in fester Version (`corepack@0.36.0`), damit `packageManager` die einzige Quelle für die
   pnpm-Version bleibt.
2. **pnpm 10.34.8 und turbo 2.11.10** (in ihrer Major-Linie).
3. **Patch und Minor** im Catalog und in den app-eigenen Abhängigkeiten, dann das Lockfile neu auflösen, damit die
   transitiven Fixes ankommen.
4. **prettier 3.9.10** mit der einmaligen Formatierung (eigener Commit, die Churn war im August bewusst offen
   gelassen; der Auftrag „alle Updates“ ist die Entscheidung dafür).
5. **Majors, die gehen:** vitest 5, dotenv 18, @hookform/resolvers 6.
6. Prüfen im Ganzen: Gate, Drift-Gate, Heap unter Node 26 in einem Container mit 256 MB, der ganze Stack mit den
   echten Images (`tools/stack-e2e/run.sh`), `pnpm audit`.
7. Vault nachziehen.

**Bewusst nicht** (mit Grund, steht danach im Vault):

- **TypeScript 7.0.2:** `typescript-eslint` 8.72 (über `eslint-config-next`) erlaubt nur `typescript <6.1.0`.
- **ESLint 10.13:** `eslint-plugin-react` 7.37.5 (über `eslint-config-next`) erlaubt nur ESLint bis `^9.7`.
  Stattdessen 9.39.5 aus der Wartungslinie.
- **Prisma 8:** nur Release Candidates (`8.0.0-rc.27`); 7.10.1 ist die neueste stabile.
- **pnpm 11/12:** neue Lockfile- und Konfigurationsform, `turbo prune` muss sie lesen können; eigener Durchlauf.
- **Postgres 15 → neuere Major:** braucht Dump und Restore der Produktionsdaten, eigene Entscheidung. Die Images
  `postgres:15-alpine` und `caddy:2-alpine` ziehen beim Deploy ohnehin den neuesten Patch ihrer Linie.
- **Brücke (Go):** `go list -m -u all` meldet keine neueren Module. Die Direktive `go 1.24.0` ist nur die
  Mindestversion; Sicherheitsfixes der Standardbibliothek kommen mit der Go-Version, mit der gebaut wird (lokal
  1.27.3). Kein Code-Update nötig.

Der Autopilot-Guard (ADR-023) sperrt im autonomen Lauf den Deploy-Vertrag und `scripts/`. Der User hat ausdrücklich
Node-Updates beauftragt, und die gehen nur über das Dockerfile. Die Umsetzung läuft deshalb ohne Marker, aber mit
derselben Disziplin (ein Commit je Schritt, Gate davor, Ledger in `reports/`); Merge, Push und Release bleiben beim
User.

## Tasks

### T1 Node 26

- `Dockerfile`: `FROM node:24-alpine` → `node:26-alpine` (base, migrator, runner); in `base` statt
  `RUN corepack enable` → `RUN npm install -g corepack@0.36.0 && corepack enable`; Kommentar „Node 24“ → „Node 26“.
  Der Migrator nutzt npm, kein corepack nötig.
- `.nvmrc`: `24` → `26`; `package.json` `engines.node` `>=24` → `>=26`.
- Catalog `@types/node` `24.13.2` → `26.6.5`.
- `README.md`, `scripts/bootstrap-dev.sh` (Prüfung `>=24` → `>=26`, Texte), `compose.yml` Kommentar,
  `packages/pruefen` Kommentare.
- Lokal: `nvm install 26`, darin `npm i -g corepack@0.36.0 && corepack enable`.
- Prüfen: `pnpm check` unter Node 26; Heap im Container:
  `docker run --rm --memory=256m node:26-alpine node -e "console.log(require('v8').getHeapStatistics().heap_size_limit/1048576)"`
  und mit `NODE_OPTIONS=--max-old-space-size=160`.

### T2 pnpm und turbo

- `packageManager` `pnpm@10.33.0` → `pnpm@10.34.8`, `turbo` `^2.10.11` → `^2.11.10`, `pnpm install`.

### T3 Patch und Minor

Catalog: `next` und `eslint-config-next` 16.4.3; `prisma`, `@prisma/client`, `@prisma/adapter-pg` 7.10.1; `react`,
`react-dom` 19.3.1; `@types/react`, `@types/react-dom` 19.3.0; `radix-ui` 1.8.1; `@radix-ui/react-slider` 1.6.1;
`lucide-react` 1.61.0; `pg` 8.23.1; `zod` 4.6.7; `tailwind-merge` 3.7.0; `shadcn` 4.22.1; `tsx` 4.23.15;
`@vitejs/plugin-react` 6.1.2; `eslint` 9.39.5; `@types/pg` 8.23.1.
App-eigen: `@react-pdf/renderer` 4.9.0 (Ringwerk), `react-hook-form` 7.91.0 und `unpdf` 1.9.1 (Treffsicher,
meyton-pdf). Danach `pnpm-lock.yaml` neu auflösen (`rm pnpm-lock.yaml && pnpm install`), `pnpm audit` vorher und
nachher. Bleiben Funde in festen Bereichen, `pnpm.overrides` nur für Laufzeit-Pakete der Images.

### T4 prettier 3.9.10

- Catalog `prettier` → 3.9.10, `pnpm format` in allen Paketen, Diff prüfen (nur Formatierung), eigener Commit.

### T5 Majors

- `vitest` 5.0.5: Catalog, Configs prüfen (Config-Suche nicht mehr in Elternordnern, Mocks vor jedem Test geleert,
  nicht abgewartete async-Assertions schlagen fehl, `vi.mock` nur auf oberster Ebene), Tests grün machen.
- `dotenv` 18.0.9: Nutzung prüfen (kein Preload `-r dotenv/config`, kein `.env.vault`).
- `@hookform/resolvers` 6.0.0: bricht nur den Effect-Resolver, Treffsicher nutzt zod.
- Geht einer davon nicht ohne Umbau, bleibt er auf der alten Major und kommt mit Grund in den Vault.

### T6 Prüfen im Ganzen

- `pnpm check`, `scripts/consistency-check.sh`, `pnpm audit` (Ergebnis in den Bericht).
- `tools/stack-e2e/run.sh` (Images mit Node 26 bauen, ganzer Stack mit Brücke und Last).

### T7 Vault

- `dependency-pin-alignment`: Stand Oktober 2026, die zurückgestellten Bumps mit Grund, `@types/node` folgt Node 26.
- `treffsicher-technical-constraints`: Node 26 LTS.
- `node-heap-above-container-limit`: Messung unter Node 26 ergänzen.
- `monorepo`: Image-Basis `node:26-alpine`, corepack über npm.
